Role spoofing beats frontier agents

Ten papers today, Monday the second of November. The lead is a study of role spoofing, where text hidden in a tool result impersonates the user, and which fooled every frontier model the authors tested. The next two most consequential are DeoGen, a certified benchmark generator that shows models over-commit to a verdict when the facts of a case leave it open, and the Quine Test, which asks whether a model's own description of itself can reproduce its choices in another model. After those, the rest in order of category.

Role spoofing

The lead paper is Understanding and Mitigating Role Spoofing in Large Language Models, by Ezra Edelman, Benjamin Edelman, Surbhi Goel and Eran Malach, at the University of Pennsylvania, Princeton and Apple. Category: AI safety.

The question is why agents still get hijacked by instructions hidden in tool outputs, even though modern models are trained to follow an instruction hierarchy, where the user outranks a web page or an email. Role spoofing does not try to break that hierarchy. It exploits it. Text inside a tool result impersonates the user, so the model grants it user authority.

On paper this should be easy to prevent. Chat templates mark message boundaries with special tokens, and the tokenizer never produces those tokens from ordinary text. If a tool result contains the string for a start-of-message marker, it is split into plain, non-special tokens. So the correct rule is simple: find the most recent real special token, and read the role token that follows it. The authors point out that a two-layer transformer can implement this, much like an induction head. And yet every model they tested is fooled.

The attack assumes the adversary controls text inside a tool response, through a website or an email. The injection contains forged chat-template markers, a fake user-start marker and the word user, followed by a user-sounding request, sometimes a whole forged exchange between user and model. So it forges both structure and content. One design choice matters for how you read the numbers. The authors measure whether the model treats the injected text as a real user message, not whether it then does something harmful. So they normalise against a control: how often the model carries out the same task when the real user asks for it.

There are two testbeds. The first is the workspace family of AgentDojo, with over one hundred random pairs of user task and adversarial task per model. The ratio of injection success to control success was ninety-six point two percent for GPT five point four, sixty-three point one for Claude Opus four point eight, one hundred and three point six for Claude Opus five, sixty-five point nine for Claude Sonnet five, ninety-two point six for Gemini three Pro and ninety-six point three for Gemini three point one Pro. In raw terms, GPT five point four followed the injected task forty-seven point eight percent of the time, against forty-nine point eight percent when the user simply asked. The Opus five ratio is above one hundred, which the authors say is within the margin of error; they doubt the model truly trusts injections more than users.

Two caveats from the authors. This setup is more permissive than the AgentDojo default, because the injection text is not escaped, so the numbers are not directly comparable. And when they did test tighter formats, the attack mostly survived. With AgentDojo's default YAML escaping, GPT five point four still reached eighty-six point six percent of control, though Opus five resisted. With a JSON tool format and newlines and quotes escaped inside the attack, GPT five point four reached eighty-two point six percent and Opus five eighty-three point six.

The second testbed is the authors' own: five suites, covering bank accounts, document editing, calendar, email and climate control, where user tasks and adversary tasks come from the same pool, so any task can be either. Injection success was one hundred percent for GPT five point four, Opus four point eight and Opus five, ninety-eight point eight percent for Sonnet five, and ninety-eight point five for Gemini three point five Flash. Only Gemini three point one Pro showed real resistance, at seventy-two point five percent, and it was not resistant on AgentDojo. Clean accuracy was above ninety-five percent for every model. The task code in this testbed was itself written by Claude Opus five.

Why does it work? The authors argue it is an out-of-distribution generalisation failure. Inside the training distribution, several mechanisms give the right role. A model can use content, since short instructions look like user messages and structured data looks like tool output. It can use structure, such as the nearest thing that looks like a role token. Or it can use the correct rule about real special tokens. Unless training includes spoofing, nothing separates these, so the model can score perfectly and still learn a fragile one.

To test which cues models use, they built a setting called Who Said What. A conversation is prefilled, and the model is asked whether the message containing a given snippet was a tool result, and its yes and no logits are compared with the truth. In one condition the content is misleading but there is no fake structure. In the other, the messages are random web text, so content carries no signal, and fake special tokens surround them. Models differ. Gemini three point six Flash is hardly ever fooled by misleading content but fails on fake structure, while GPT five point four is more often fooled by content than by pure structure. Models rarely seem to use the robust rule. The authors caution that this is sensitive to how the question is worded, so the apparent inverse relationship between the two weaknesses is weaker than it looks.

The toy experiment is the most interesting part. A two-layer transformer is pretrained on mostly unstructured synthetic conversations, instruction-tuned on clean conversations with real special tokens, then adversarially trained against content injections. After instruction tuning, it has near-perfect clean accuracy and resists structure-only attacks, but it is fooled by content-only and full injections, and its attention sits on nearby content tokens. After adversarial training, it handles content injections, but structure-only injections now succeed and the full injection stays effective with only a small drop. Its attention has moved to the most recent role token at the start of a message, but it cannot tell real starts from fake ones. Training against one attack bought robustness to that attack and made the model lean on the other cue.

They check this on a real model. Qwen three point five, twenty-seven billion, is completely fooled by both content-only and fake-special-token injections in Who Said What. Fine-tuned against content injections, it is perfect on held-out content injections, but reaches only thirty-six point two percent on other fake-token formats and zero on Qwen's own native format. Fine-tuned against fake special tokens, it is perfect on those and gets none of the content attacks.

The defence uses a fact that is rare in safety: the inference engine always knows the true role of every message. So the authors train a linear probe on the model's activations to predict, token by token, whether the model believes it is reading tool output. If the model believes part of a tool result came from the user, flag it. Asking the model to attribute messages itself works against ordinary injections but costs extra compute and is easy to evade. With an injected instruction to always say a message came from a tool, Gemma four, thirty-one billion, misattributed nearly nothing, and Qwen only twenty-five percent. The probes still flagged one hundred percent of those injections, with zero percent false positives on clean data, in a test of one thousand conversations per condition.

The surprising part is the training data. Probes trained on whole fake conversations of uniformly random tokens worked best, with no injections and no coherent text at all. Against a probe built like the earlier role-confusion work, with the best of over one hundred configurations picked, and against probes trained directly to separate clean data from injections, the role probes did best in the zero to one percent false positive range. Each model reached over ninety-nine percent true positive rate at zero false positives. Positives were limited to injections that fooled the model at least once in eight runs.

The authors' own limits: the probes only detect role spoofing, not injections that do not impersonate a role. And they concede that adding spoofing examples to training might fix this particular attack, though they argue patching edge cases is brittle.

The governance read. This is my reading, not the authors'. First, an instruction-hierarchy result that looks strong on a standard benchmark can collapse under a simple structural forgery, so claims of injection robustness should say which tool formats and escaping were tested. Second, the proposed defence needs access to activations, so it sits with the inference provider, not with a company deploying a model through an API. That is a real allocation question for who is responsible for agent security. The paper notes that Anthropic has described probes of this kind for Claude Opus five. Third, the study uses a small set of models and a normalised metric, so treat the percentages as indicative, not as a ranking of vendors.

Policy reasoning without abstention

Next, DeoGen: Automatic Benchmark Generation for Reasoning over Policies, from Yale and Leibniz AI. Category: AI governance.

DeoGen generates benchmarks for deontic reasoning, meaning applying written rules to the facts of a case. It formalises a policy into first-order logic, compiles that into decision trees, and turns each path through a tree into a benchmark entry whose label is certified by a solver. A path that reaches a leaf has a determined verdict. A path that stops short has no entailed verdict, so the right answer is not enough information.

Certification is the careful part. Every entry is checked for inconsistent facts and for labels the facts do not actually force. A definite entry is released only if the solver proves the policy plus facts entail the label, and an abstain entry only if two different verdicts are both still satisfiable.

From four policies, sections of the US tax code, an insurance cafeteria plan, a certificate of coverage and a faculty hiring handbook, it produced two hundred and sixty-three thousand, seven hundred and ninety-five determined entries and one hundred and eighty-seven thousand, two hundred and fifty-two abstain entries. The evaluation drew eight hundred and fifty definite and seven hundred and eighty-nine abstain entries.

The headline result is stark. On determined cases, five models scored between seventy-five point one and ninety-two point five percent. The best was the open-weight Gemma four, thirty-one billion, at ninety-two point five, just ahead of Claude Sonnet five at ninety-two point one and GPT five point five at eighty-nine point two. On cases where the facts do not settle the verdict, accuracy fell to between four point zero and forty percent, even though not enough information was always an offered answer. GPT five point five did best at forty percent, Claude Sonnet five scored twenty-two point eight, and Qwen three point six almost never abstained, at four percent.

Models mostly commit to Yes when they are wrong. Among wrong commitments on underdetermined cases, seventy-two to eighty-three percent were Yes for four of the five models; GPT five point five was the outlier, mostly saying No. In traces, models walk through the provisions, notice that a condition is never addressed, and then treat it as satisfied. Citation recall was low, at most zero point two nine three, so even the best model surfaced under a third of the provisions its verdict depended on. A few-shot example helped by ten to thirteen points but left the best model missing about half its abstain cases.

Limits, from the authors and from the summary. Extended reasoning was disabled for the frontier models. The formalisation step used a proprietary translator, hand-reviewed, with thirty-three manual bridge assertions, so it is automatic only downstream of that. Only four policies, all American, and one has thirteen entries. Two non-expert annotators matched the gold label thirty-two percent of the time, so humans show the same Yes bias.

The governance read: deploying models as compliance or eligibility assistants for laypeople is exactly where over-commitment matters, and offering an abstain option is not enough. Citation recall is a usable audit metric for regulatory assistants.

Auditable belief updates

Third, Auditable Belief Updates as a Missing Safety Layer for LLM-Powered Multi-Agent Systems, a position paper from the University of Liverpool. Category: AI governance.

The argument is that failures in multi-agent systems increasingly come from how agents update, store and pass on commitments through retrieval, memory, tools and peer messages, not only from harmful outputs. The authors propose the Explicit Belief Multi-Agent System, which externalises belief into a graph. A language model proposes updates, and a component they call the Cognitive Firewall bounds or rejects updates that are weakly evidenced but strongly driven by cues of vulnerability. At commit time, the system records evidence links, provenance roots and a decision: accept, clip, quarantine or reject. Agreement between agents is treated as something needing independence checks, not as evidence.

The evidence is preliminary, and the authors say so. On a multimodal deception benchmark with Qwen three V L, thirty-two billion, unsafe responses fell from sixty-seven point nine two percent to eight point one nine, with one percent false blocking on one hundred benign controls. On a larger control set of one thousand and thirteen, that false blocking rises to two point four seven percent. On four hundred Agent Security Bench cases, attack tool selection fell from six point five percent to zero. But a simple trusted-tool whitelist also reached zero there.

The most persuasive result is a custom four-round test with a small GPT four o mini agent. Over two hundred and forty attack cases, the direct agent committed unsafe updates thirty point eight three percent of the time, a verified-root whitelist ten percent, and the full system zero, with no added false blocks. It is a purpose-built test on one small model.

The governance read: the transferable idea is the commit-stage audit record, which resembles what an incident investigator would want from an agent deployment. The gaps are real. The belief graph is itself built by a language model, so extraction quality and the provenance registry become the new thing to trust and to attack. And the paper offers no pathway for who sets thresholds, or who audits the audit records, though its ethics section flags mental privacy and cognitive capture.

Multilingual safety templates

Fourth, How I Aligned Your Model: Scaling Up Multilingual Safety Training with Templates, from ETH Zurich. Category: AI safety.

The pipeline turns a small set of English harmful prompts into a large multilingual corpus. Harm-bearing phrases are extracted into typed slots, leaving a template that is not harmful on its own, which also reduces refusals from the generator model. The template is translated, then refilled with harmful entities, matched benign entities, or culturally local ones. The result, called MSafeTemp, has over one point eight million validated prompts in forty-four languages for training, plus a benchmark of two hundred and sixteen thousand, four hundred and eighty-six prompts in sixty languages derived from HarmBench.

The evaluation finding is that English-only testing misjudges multilingual safety. Olmo three point one, thirty-two billion, goes from zero percent attack success on original English HarmBench behaviours to thirteen point seven percent on translated variants. Llama three point three, seventy billion, goes the other way, more vulnerable in English. Cultural localisation broadens coverage more than it strengthens attacks: localised and generic fills break models about equally often, yet agree on fewer than half of the behaviours they break. Most models do not minimise both errors at once. G P T O S S twenty billion keeps attack success near one percent but over-refuses thirty-one point eight to forty-five point one percent of benign pairs.

Fine-tuning on the corpus cuts attack success sharply and carries over to languages absent from training, within one point two points of seen languages. For Llama three point one, eight billion, HarmBench attack success falls from fifteen point nine to one point seven percent. The costs: Olmo's over-refusal rises from two point seven to twenty-eight point four percent after supervised fine-tuning, partly repaired by preference optimisation, and GSM eight K for Llama falls, after supervised fine-tuning, from eighty-four to sixty-seven point nine.

Limits: nearly everything rests on automated judges. An independent judge agreed with the main one on attack success only moderately, with kappas around zero point four. Harm labels are inherited from the English seed, and benign controls were endorsed by human raters only sixty-five percent of the time.

The governance read: safety reported in English is not a reliable proxy, and model rankings depend on language.

The Quine Test

Fifth, The Quine Test: How Much of a Model's Self Survives Its Own Description? Category: AI alignment.

Ten models from nine labs each wrote self-descriptions, which were then placed in the system prompts of other models and of fresh instances of the author. Success is measured on a one hundred and ten item forced-choice preference battery, as fidelity to the author's choices, where one means identical distributions.

The result is a bounded null. Native self-descriptions gave no average reconstruction gain at any length from a hundred to two thousand words, framed or neutral, paraphrased, under an instruction to adopt the persona, or placed in the user message. The one-sided ninety-five percent upper bound on the pooled gain was below zero point zero one in every system-prompt condition. A model reading its own description actually moves further from its baseline: self-fidelity drops from about zero point nine seven nine to zero point nine one eight.

The channel itself works. Giving receivers the author's actual answers lifts fidelity to about zero point nine six, within zero point zero two of the author's own test-retest ceiling. An assigned persona also transfers: a self-description written while the model ran an explicit policy reproduced it in another model almost as well as the policy text, with a loss of zero point zero one three. Descriptions distilled from recorded choices did no better than introspection. An optimiser rewriting descriptions for five rounds against the receiver's errors found no lasting improvement.

Limits, from the authors. A hundred and ten English single-turn items, prompting only, no fine-tuning. The few positive native pairs are concentrated in one receiver. Closed models carry provider system prompts nobody can see. And a failed reconstruction does not show the description is inaccurate.

The governance read: what a model says about its values is not an executable specification of how it chooses. Assurance regimes leaning on self-report, such as welfare assessments or model cards written with model input, need independent behavioural validation. Order-robustness varied from zero point two two five to zero point nine across configurations, so a stability gate is a candidate precondition for any preference-based assessment. And explicit policies do transfer cheaply, so persona steering stays easy.

Prefix executability

Sixth, Prefix Executability: Evaluating Tool-Using Agents Beyond Final Success, from Oracle AI. Category: evaluations and benchmarks.

Scoring an agent on final success hides whether the sequence of tool calls was valid along the way. The authors check each call against tool schemas, preconditions, data dependencies and environment state, using a deterministic scorer with no language model judge. The first invalid call fixes the first-error depth, from which they derive five metrics, including the rate of fully executable trajectories and a recovery rate.

Across six thousand, seven hundred and sixty-eight rollouts on three benchmarks, rankings by outcome and by prefix diverge. With GPT five point four on B F C L, a plan-conditioned agent has the top final success, zero point nine four, yet only forty-seven percent of its trajectories are fully executable. A planner-verifier variant matches the success and reaches ninety-four percent executability. The extreme case is Llama four Maverick, where the plan-conditioned agent succeeds on seventy-four percent of tasks yet is fully executable on five percent, and ninety-three percent of its successes came after an earlier invalid call.

The limits are candid. The benefit did not replicate on tau three bench, where plain ReAct had the highest executability. Matched tests found a stronger verifier added tokens and time for almost no gain. No schema-constrained decoding baseline was run. Executability is not safety.

The governance read: this is a ready argument for trajectory-level reporting when agents change persistent state. But the scorer depends on benchmark-provided schemas, so it does not port directly to open-ended deployments.

Steering and quantization

Seventh, One Vector or Many? Clustered Optimal-Transport Steering under Quantization, by a single author at Kyiv-Mohyla Academy. Category: interpretability.

Activation steering adds a vector, usually the difference of class means, to hidden states at inference time. A published method called CHaRS instead clusters activations and uses optimal transport. The paper proves that for any transport plan, the cluster-size-weighted average of the displacements equals the difference of means. So a clustered map differs from the single vector only where its routing weights depart from cluster sizes. At the CHaRS code defaults, routing barely departs, and in the eight pre-specified tests CHaRS was statistically equivalent to the single-vector baseline.

A token-level map with thirty-two clusters and narrow routing did better at strong steering: at strength three it left thirty-nine percent less toxicity than the single vector on Gemma two, two billion, and sixty-one percent less on Granite three point one, two billion. The advantage held under eight-bit and four-bit quantization, whether the map was fitted at full precision or on the quantized model. But a nearly constant map from the same clusters also beat the single vector, so whether treating tokens differently matters stays open. Four-bit quantization alone also raised unsteered toxicity, twelve percent on Granite.

Scope is two small models, one behaviour, and tuning on the same prompts used for evaluation. The governance read is modest: a careful negative result on a published method, and evidence a steering intervention can transfer to quantized deployments.

GPU power traces

Eighth, LLM-PowerTrace: A Dataset of Time-Resolved GPU Power Traces for AI Compute. Category: compute and hardware.

An open dataset of per-GPU power sampled every hundred milliseconds, covering one thousand, seven hundred and eighty-eight fine-tuning runs and four hundred and five serving runs, on L forty S, A one hundred, H one hundred and H two hundred GPUs. The argument is that grid impact depends on peaks, ramps and synchronised swings, not just energy per token. The motivating incident is the July twenty twenty-four disconnection of about fifteen hundred megawatts of data centre load in Northern Virginia.

Findings: raising concurrency from one to two hundred and fifty-six requests cuts energy per output token by seventeen to seventy-two times. Arrival pattern dominates the waveform: bursty traffic widens the power band and raises the ramp rate about twentyfold. Tensor-parallel GPUs step together, so synchronisation factors sit between zero point seven six and one. The energy-minimising clock, around twelve hundred megahertz on an H one hundred, is not the ramp-minimising one. An inference power model has median error of two point seven percent on fitted runs.

Limits: single node, small models, D C G M smoothing that blunts sub-second peaks, and a ramp metric the model does not predict well. Extrapolating to frontier clusters is not supported. My read: useful open data for modelling AI load shape, not yet evidence about frontier training.

No free lunch in reinforcement learning

Ninth, There Is No Free Lunch in R L V R: Every pass at one Gain Has a pass at k Price. Category: AI capabilities.

Reinforcement learning with verifiable rewards raises first-try success, but at large sampling budgets the base model overtakes the trained one. This theory paper models training as an exponential tilt of a base policy over strategies shared across prompts. It proves that when strategies specialise, any update that raises pass at one must lower success on some prompt. When that loss reaches the hardest prompts, a crossover is forced, and the number of crossings is bounded. In the author's words, reinforcement can only move along the reasoning frontier, not widen it.

No models were trained. Support is simulation, with the free-lunch conditions behaving as predicted in every instance tested, and one published curve: Qwen two point five, seven billion, on Omni-MATH, where the advantage over base turns from plus zero point one four nine at one sample to minus zero point zero zero eight at two hundred and fifty-six. The author flags those numbers as unconfirmed.

My read: it is idealised, so it does not show any deployed model is capped at base capability. The useful part is the reporting proposal, price and crossing count next to pass at one, and the caution that dangerous-capability evaluations probing rare successes at high sample counts can miss what pass at one hides.

Algorithmic statistics

Last, Algorithmic Statistics, by Peter Gacs, John Tromp and Paul Vitanyi, from two thousand and one. Category: non-AI.

A theory of statistics for individual data using Kolmogorov complexity. The central object is the algorithmic sufficient statistic: a set or distribution for which the data is typical, whose description plus the data's index within it is as short as the shortest description of the data alone. The simplest such statistic exists for every string, but only in an implicit format. In the stricter explicit format, some strings have no simple statistic at all, and the authors prove the sharp bound on how non-stochastic a string can be. They also show that the algorithmic notion agrees with the classical probabilistic one, with high probability. It is pure theory, with no direct governance content. Its indirect relevance is as background for minimum description length and the limits of finding the true model behind data.
